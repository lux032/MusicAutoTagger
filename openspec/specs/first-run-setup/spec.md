# first-run-setup Specification

## Purpose

规范 Music Auto Tagger 首次启动时的待命保护、多步初始化引导（账号与语言、目录与代理、识别数据源、AI 与联网搜索、整理偏好）、配置连通性校验、引导完成后进程内激活监控，以及老用户升级兼容与跳过补救的可观测行为。

## Requirements

### Requirement: 首次全新启动进入待命状态，防止未配置前误扫描
当应用处于全新未初始化状态（既无初始化完成记录，也无既有管理员凭据）时，系统 SHALL 仅启动 Web 面板与初始化所需的基础服务，并保持文件监控与自动识别流水线处于待命状态，MUST NOT 在初始化完成前扫描监控目录或处理音频文件。

#### Scenario: 全新启动时监控目录已有待处理文件
- **WHEN** 用户首次部署应用，且监控目录中已存在音频文件、配置文件仍为默认模板（例如未填写有效 AcoustID API Key）
- **THEN** Web 面板可正常访问并进入初始化引导界面
- **AND** 系统不扫描该目录、不向识别源发起指纹查询，也不移动、改名或写入任何音频文件

#### Scenario: 待命状态下访问业务接口受保护
- **WHEN** 系统处于未初始化待命状态，客户端请求仪表板、待确认、恢复或处理记录等业务 API
- **THEN** 未登录请求返回 `401`，已登录但尚未完成初始化的业务请求返回明确状态提示要求完成初始化引导，且不产生空指针或 500 崩溃

### Requirement: 老用户升级兼容与无感平滑过渡
当应用启动时已存在既有管理员凭据（即使缺少初始化状态文件），系统 SHALL 将该实例视为已完成初始化，直接按正常流程启动全部业务服务与文件监控，MUST NOT 强行拦截老用户进入全屏初始化引导。

#### Scenario: 老版本升级后首次重启
- **WHEN** 已有管理员账号的实例升级到包含初始化引导的新版本后启动
- **THEN** 系统正常初始化全部服务并启动文件监控
- **AND** 用户打开 Web 面板后直接看到正常登录页（或已登录的概览页），不被强制跳转至初始化引导

#### Scenario: 管理员在设置页主动重新运行引导
- **WHEN** 已登录管理员在设置页点击「重新运行初始化引导」
- **THEN** 系统打开初始化引导并自动跳过「创建管理员」步骤，从「目录与网络」步骤开始，且回填当前已保存的非敏感配置与密钥占位态
- **AND** 若用户在该次重跑中修改了需重启生效的配置（如监控目录、输出目录或 HTTP 代理），提交后系统明确提示需重启服务生效并提供快捷重启操作，不破坏运行中的服务状态

### Requirement: 5 步初始化引导覆盖核心与可选配置且支持实时语言切换
Web 面板 SHALL 提供独立的 5 步初始化引导流程，依次引导用户完成：1) 语言与管理员账号、2) 目录与 HTTP 代理、3) 识别数据源（AcoustID 与 MusicBrainz）、4) AI 与联网搜索（可选）、5) 整理偏好与配置总览确认；并允许在引导任意页面即时切换中英文界面。

#### Scenario: 第 1 步实时切换界面语言并创建管理员
- **WHEN** 用户首次打开 Web 面板进入第 1 步，将语言从英文切换为简体中文（或反向切换）
- **THEN** 页面所有标题、说明、表单标签与按钮文案立即刷新为所选语言，无需先登录或刷新页面
- **AND** 用户输入有效用户名与不少于 8 位密码并提交后，系统创建管理员凭据、建立已认证会话并返回 CSRF 令牌，随后进入第 2 步

#### Scenario: 第 1 步展示运行环境自检摘要
- **WHEN** 用户进入第 1 步初始化界面
- **THEN** 系统展示当前运行环境的基础就绪状态（包括 `fpcalc` 可用性、`ffmpeg` 可用性以及默认 SQLite 存储就绪状态）
- **AND** 若 `fpcalc` 不可用，界面给出清晰的非阻塞提示说明音频指纹识别将受限

#### Scenario: 第 2 步校验目录并按需配置 HTTP 代理
- **WHEN** 用户在第 2 步查看或修改监控目录与输出目录，并可选开启 HTTP 代理填写主机、端口与认证信息
- **THEN** 系统检验并展示监控目录的存在性与可读状态、输出目录的存在性与可写状态
- **AND** 若启用了 HTTP 代理，后续步骤的连通性校验与模型拉取请求均使用该临时代理配置，无需先重启服务

#### Scenario: 第 3 步配置核心识别数据源并自动格式化 User-Agent
- **WHEN** 用户进入第 3 步且配置中的 AcoustID API Key 为默认占位值（如 `YOUR_API_KEY_HERE`）
- **THEN** 界面将其视作未配置状态并提示用户前往 AcoustID 获取有效密钥，而非展示为已掩码有效密钥
- **AND** 当用户在 MusicBrainz 联系邮箱输入框填入有效邮箱时，界面自动预览并生成符合规范的 `User-Agent` 字符串（同时允许用户切换为自定义完整 `User-Agent`）

#### Scenario: 第 4 步可选配置 LLM 供应商、模型与联网搜索源
- **WHEN** 用户在第 4 步添加或编辑 LLM 供应商（名称、协议格式、API URL、API Key），点击拉取模型列表并勾选参与工作的模型，同时在 `tavily` 与 `native` 间选择联网搜索来源
- **THEN** 系统返回可用模型列表并在仅填域名时给出建议完整 API 路径回填提示，同时允许手动添加模型名作为兜底
- **AND** 选择 `tavily` 时展示 Tavily API Key 输入与测试入口，选择 `native` 时允许在模型行上勾选原生联网搜索开关
- **AND** 若用户暂不需要 AI 功能，可直接点击「跳过此步」进入第 5 步，不阻塞初始化流程

#### Scenario: 第 5 步配置整理偏好并展示总览清单
- **WHEN** 用户进入第 5 步
- **THEN** 界面提供核心整理策略选择（遇到不确定专辑进入待确认队列或自动归档、缺封面拦截开关、发行地区优先级快捷预设、优先动画盘封面、导出独立 `.lrc` 歌词）以及前序步骤的配置总览清单
- **AND** 总览清单以脱敏方式呈现所有凭据配置状态（已配置/未配置/已验证），MUST NOT 明文回显任何 API Key 或密码

### Requirement: 引导步骤内的安全连通性校验
系统 SHALL 为已通过第 1 步认证的管理员提供引导阶段的配置校验能力（目录读写校验、HTTP 代理连通性测试、AcoustID API Key 与 MusicBrainz 可达性测试、Tavily API Key 测试），并严格遵守防 SSRF 与只读配置安全边界。

#### Scenario: 校验接口强制认证与防 CSRF
- **WHEN** 未登录客户端或缺少有效 CSRF 令牌的请求调用目录校验、代理测试、数据源测试或初始化完成提交接口
- **THEN** 系统拒绝该请求（未登录返回 `401`，CSRF 无效返回 `403`）

#### Scenario: 代理与数据源测试返回明确诊断结果
- **WHEN** 管理员在第 2 步测试 HTTP 代理、在第 3 步验证 AcoustID 与 MusicBrainz，或在第 4 步测试 Tavily
- **THEN** 系统使用当前向导中的临时配置（含未落盘的代理设置）执行有限超时的外部探测，并返回结构化结果（成功与延迟，或明确的失败原因如「AcoustID API Key 无效」「代理认证失败」「连接超时」）
- **AND** 代理连通性测试仅探测系统内置的固定受控音乐元数据端点，不接受任意目标 URL 参数；LLM 模型拉取继续受 `llm.allowPrivateEndpoints` 与公网地址校验约束

#### Scenario: 只读安全配置在初始化流程中仍不可修改
- **WHEN** 客户端在引导提交载荷中尝试篡改只读安全配置（例如 FFmpeg 可执行路径、允许内网 LLM 端点开关、SQLite 数据库路径、队列或回收站路径）
- **THEN** 系统拒绝或忽略此类非法修改，保持只读安全边界与配置页完全一致

### Requirement: 引导完成后进程内原子落盘并激活监控
当全新启动的实例在第 5 步提交完成初始化时，系统 SHALL 原子保存所有配置与初始化完成标记，并在当前进程内基于最终配置一次性初始化核心业务服务与文件监控，MUST NOT 要求用户手动重启进程才能使首次设置的目录与代理生效。

#### Scenario: 全新启动完成引导后无缝进入运行态
- **WHEN** 全新启动的管理员在第 5 步点击「完成并启动监控」
- **THEN** 系统将语言、目录、代理、AcoustID、MusicBrainz、Tavily、整理偏好写入 `config.properties`，将已配置的 LLM 供应商写入供应商配置文件，并持久化初始化完成标记
- **AND** 系统使用最终配置在进程内完成核心服务初始化与文件监控启动，前端随后跳转至概览页并显示监控已运行

#### Scenario: 激活失败时保留引导页并给出可恢复错误
- **WHEN** 引导完成提交过程中配置写入失败或关键目录不可用导致初始化失败
- **THEN** 系统不标记初始化完成，保留当前引导表单状态并向用户返回明确错误原因，允许修正后重试

### Requirement: 允许暂缓 AcoustID 配置并在概览页提供补救提示
系统 SHALL 允许用户在第 3 步显式选择「稍后再配」以跳过 AcoustID API Key 完成初始化；当系统进入正常运行态且 AcoustID API Key 仍为空或占位符时，概览页 SHALL 展示一条非阻塞的轻提示横幅引导补全。

#### Scenario: 跳过 AcoustID 完成初始化后展示概览提示
- **WHEN** 用户在第 3 步选择稍后再配并完成第 5 步启动服务
- **THEN** 系统正常启动并进入概览页
- **AND** 概览页顶部展示轻提示横幅，说明缺少 AcoustID API Key 将导致音频指纹识别不可用，并提供「补全配置」直达入口与「忽略」操作

#### Scenario: 补全有效 AcoustID Key 或忽略提示后横幅消失
- **WHEN** 用户通过设置页或重跑引导填入了非空且非占位符的 AcoustID API Key，或在横幅点击「忽略」
- **THEN** 概览页不再展示该缺失提示横幅（忽略状态跨刷新保留）
