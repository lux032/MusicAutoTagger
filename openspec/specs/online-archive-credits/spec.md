# online-archive-credits Specification

## Purpose

规范用户在待确认流程中执行联网归档时，对每首曲目作曲、作词、编曲标签的多源合并优先级、界面预览与人工修正、显式清空、缺封面中转持久化以及单文件重识别元数据衔接的完整行为。

## Requirements

### Requirement: 按确定优先级逐字段合并曲目级幕后人员
在用户确认联网候选并归档音频文件时，系统 SHALL 对每首曲目的作曲、作词、编曲三个字段各自独立按 `手动编辑 > MusicBrainz 指纹识别结果 > 本地文件已有标签 > 联网搜索提取结果` 的优先级计算最终写入值，且仅允许通过确定性核验的非冲突联网字段参与自动合并。

#### Scenario: 四类来源并存时按优先级独立生效
- **WHEN** 同一首曲目同时存在 MusicBrainz 作曲、本地文件已有作词、联网核验通过的编曲，且用户未手动修改该曲目
- **THEN** 归档文件写入 MusicBrainz 的作曲及其对应的 MusicBrainz ID、保留本地文件的作词，并用联网结果补全空白的编曲
- **AND** 联网补全的编曲写入标准编曲标签与结构化复数伴随标签，且不写入任何虚构的 MusicBrainz ID

#### Scenario: 本地文件已有标签不被联网提取结果覆盖
- **WHEN** 曲目没有 MusicBrainz 指纹结果，但本地音频文件已包含作曲标签且联网候选也提取了不同的作曲名单，用户未在确认弹窗中手动修改
- **THEN** 归档文件保留本地音频文件原有的作曲标签，不以联网提取结果覆盖

#### Scenario: 低置信度匹配曲目不套用联网幕后人员
- **WHEN** 某首本地文件与联网候选曲目的匹配置信度低于可靠匹配阈值（`0.6`），且用户未手动指定该曲目的幕后人员
- **THEN** 系统忽略该联网候选曲目携带的作曲、作词、编曲名单，仅依据更早阶段已有的 MusicBrainz 结果或本地文件标签落盘

#### Scenario: 冲突或未核验通过的联网字段不自动写入
- **WHEN** 某首曲目的联网幕后人员字段核验状态为 `conflict`、`not_found` 或 `not_searched`，或配置关闭 `online.credits.applyProbable` 时字段状态为 `probable`，且用户未在确认弹窗中手动选择或填写
- **THEN** 系统不自动采用该联网字段值，仅沿用更高优先级的 MusicBrainz 或本地标签（均为空时留空）

### Requirement: 联网确认支持预览、编辑与显式清空幕后人员
系统 SHALL 在待确认详情与联网确认交互中向用户展示即将写入的曲目级幕后人员、来源标记、证据核验状态、来源链接、原文证据摘录及冲突候选，并允许用户在提交联网归档时对单首曲目的作曲、作词或编曲进行点选采用、修改或显式清空。

#### Scenario: 候选详情与确认弹窗展示幕后人员与来源
- **WHEN** 用户在待确认页面选中一个联网候选并打开确认归档弹窗
- **THEN** 候选详情区在匹配曲目下紧凑显示已识别的作曲、作词、编曲信息及其证据状态标记（如 `已核验`、`推测`、`冲突`）
- **AND** 确认弹窗提供可折叠的逐曲幕后人员区域，按合并规则展示每首曲目即将写入的名单、对应来源标记（`MusicBrainz`、`本地`、`联网·已核验`、`联网·推测`、`手动`），并可查看联网字段对应的可点击来源 URL 与原文证据摘录

#### Scenario: 存在来源冲突时在弹窗中展示多候选供人工点选
- **WHEN** 某首曲目的联网幕后人员字段状态为 `conflict` 且携带多个冲突候选
- **THEN** 确认弹窗默认不自动预填该字段，并在该字段下方列出各冲突候选的人名、来源链接与引文，允许用户一键填入其中一项或手动输入

#### Scenario: 人工修改幕后人员覆盖自动结果并清理旧 ID
- **WHEN** 用户在确认弹窗中修改某首曲目的作曲名单并提交联网归档
- **THEN** 归档后的音频文件写入用户修改后的作曲显示名与结构化复数名单
- **AND** 原音频文件中可能残留的旧作曲 MusicBrainz ID 标签被一并清除

#### Scenario: 人工显式清空幕后人员删除音频内既有标签
- **WHEN** 某首曲目原本包含作曲、作词或编曲标签，用户在确认弹窗中将该字段显式清空并提交归档
- **THEN** 系统从归档后的音频文件中彻底删除该字段对应的标准标签、结构化复数伴随标签以及对应的 MusicBrainz ID 标签

#### Scenario: 未传逐曲幕后人员参数时保持向后兼容
- **WHEN** 调用方提交联网确认请求时未提供逐曲幕后人员覆盖字段，或待确认条目为升级前落盘且缺少 `creditDetail` 字段的历史队列条目
- **THEN** 系统按既有接口语义正常渲染与完成归档，并自动应用默认的多源合并优先级

### Requirement: 人工编辑的幕后人员跨缺封面拦截流程持久化
当联网确认因缺少封面转入「缺少封面」等待队列时，系统 SHALL 持久化用户已确认的逐曲幕后人员覆盖，并在后续补全封面或确认无封面入库时原样生效。

#### Scenario: 缺封面中转与服务重启后仍保留人工编辑结果
- **WHEN** 用户在联网确认弹窗中编辑了逐曲幕后人员且未提供可用封面，条目被拦截并转入「缺少封面」队列，随后用户在「缺少封面」页面选择封面或确认无封面入库（包括中途经历进程重启）
- **THEN** 最终落盘的音频文件完整应用此前保存的人工幕后人员修改与显式清空结果

### Requirement: 单文件隔离重识别转入联网归档不丢失已有 MusicBrainz 幕后人员
当来自隔离目录的单个音频文件先经普通重新识别从 MusicBrainz 获取了曲目级幕后人员并进入待确认，之后由用户通过联网候选归档时，系统 SHALL 正确关联并保留此前获取的 MusicBrainz 作曲、作词、编曲信息。

#### Scenario: 单文件隔离项重识别后再走联网归档
- **WHEN** 隔离目录中的单文件执行普通重新识别，指纹成功拉取了 MusicBrainz 作曲、作词或编曲但因专辑未定进入待确认队列，随后用户为其执行联网搜索并确认归档
- **THEN** 归档后的音频文件保留该单文件在重新识别阶段获取的 MusicBrainz 幕后人员标签及其对应的 MusicBrainz ID
